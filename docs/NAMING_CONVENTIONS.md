# Тармақтар, тапсырмалар және коммиттерді атау келісімі (Naming Conventions)

«SmartUniver» жобасының барлық қатысушылары үшін код пен тапсырмаларды басқарудың бірыңғай тәртібі міндетті болып табылады.

---

## 1. Тапсырмаларды (Issues) атау келісімі

Әрбір тақырып (Issue Title) міндетті префикстен басталып, тапсырманың мәнін қысқа, нақты қазақ тілінде түсіндіруі қажет:

* `[FEAT] <Сипаттама>` — Жаңа функционал қосу (Feature request)
* `[BUG] <Сипаттама>` — Қатені түзету (Bug fix)
* `[TASK] <Сипаттама>` — Техникалық немесе ұйымдастырушылық тапсырма (Technical task)
* `[SPIKE] <Сипаттама>` — Зерттеу, архитектуралық сараптама немесе прототиптеу (Research / Discovery)
* `[DOCS] <Сипаттама>` — Құжаттама, ADR немесе вики жазу

**Мысалдар:**
* `[SPIKE] Университеттің ескі деректер базасының REST API шлюзін зерттеу`
* `[FEAT] Студенттің жеке кабинетінде сабақ кестесін көрсету экраны`
* `[BUG] iOS қосымшасында авторизациядан өту кезіндегі 500 қатесін жөндеу`
* `[DOCS] docs/adr/ADR-001-delivery-model.md архитектуралық шешімін жазу`

---

## 2. Git тармақтарын (Branches) атау келісімі

Барлық тармақтар кіші әріптермен, дефис арқылы және тапсырманың идентификаторымен (ID) жазылады.

**Үлгі:**
`<түрі>/SU-<нөмірі>-<қысқа-сипаттама>`

* `feature/SU-12-schedule-screen`
* `fix/SU-45-auth-token-refresh`
* `docs/SU-01-adr-delivery-model`
* `spike/SU-03-legacy-db-connection`

**Тармақ префикстері:**
* `feature/` — Жаңа мүмкіндіктер мен модульдер
* `fix/` — Қателіктер мен ақауларды түзету
* `docs/` — Құжаттама мен регламенттер
* `spike/` — Зерттеу және гипотеза тексеру
* `hotfix/` — Продакшндағы шұғыл ақауларды жою

---

## 3. Коммиттерді (Git Commit Messages) атау келісімі

Conventional Commits стандартына сүйенеді:
`<түрі>(SU-<нөмірі>): <орындалған әрекет>`

**Мысалдар:**
* `feat(SU-12): add weekly timetable view component`
* `fix(SU-45): resolve null pointer exception during SSO login`
* `docs(SU-01): finalize ADR-001 delivery model selection`
* `chore(SU-02): initialize github projects board and workflow`

---

## 4. Pull Request (PR) ережелері
1. PR тақырыбы тармақ атына сәйкес болуы керек.
2. PR сипаттамасында жабылған тапсырма нөмірі көрсетіледі: `Closes #12`.
3. Кемінде 1 команда мүшесінің мақұлдауы (Code Review) міндетті.
